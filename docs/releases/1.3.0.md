# v1.3.0

## 新增：双站点支持（sub / www）

鱼鱼API 现在有两套独立后端，接口形状一致但**账号与 token 互不通用**（同一邮箱在 sub 是 id=366、在 www 是 id=1859173037），插件此前只认 `sub.anzhiyu.com`。

- **站点注册表**（新 `lib/sites.ts`）：`sub` / `www` 各自的 API 根地址、使用记录页与充值中心地址集中一处维护。
- **账号按站点记账**：账号唯一键改为 `<site>:<email>`，同一邮箱可以在两个站点各存一份余额；旧配置里的裸邮箱自动迁移为 `sub:` 前缀，无需手动改文件。
- **浏览器同步按 origin 分站点**：从 leveldb 记录前的 `_https://<host>` 标记判定每条登录态属于哪个站，refresh token 只与本站点配对，不会跨站串号；验证 token 时也打它自己的站点（sub 的 token 在 www 上必然是 401）。
- **续期 / 充值 / 使用记录跟着账号走**：`/auth/refresh` 发往账号自己的站点；「充值」按钮与失效提示按当前站点打开对应页面。
- **界面**：设置页账号行与页眉新增站点徽标（`sub` / `www`），切号时一眼能分清钱包。
- **手动贴 token**：不带站点信息，先试当前站点，失败自动试另一个站点。

## 修复：PTC（run_code）工具注册

- 工具输出 schema 此前写成 `{ type: 'array', items: { type: 'json' } }`，而 DSH 只接受 `object/array/string/number/integer/boolean/null` 七种类型：注册时抛 `JsonSchemaError`，工具实际没注册成功；即使注册上了，PTC 生成的 TypeScript 绑定也会因 schema 不合法退化成 `unknown`。现改为合法的 `{ type: 'object', properties: { text } }`，`execute` 返回对应的规范 JSON 值（而不是 ContentBlock 数组）。
- `parameters` 此前传的是 `properties` 映射而不是完整 JSON Schema，PTC 侧据此把参数类型渲染成 `unknown`；现在传 object 根，参数在 `run_code` 里能正确补全。

## 新增：子 Agent 完成通知开关

- 设置页「提醒」组新增 **子 Agent 完成时通知** 开关（对应 `notifySubagentMute`）。关闭后子会话的轮次不再弹系统通知、应用内气泡与角标，只更新报告数值；打开时通知标题会标注「子 Agent ·」，便于分辨来源。
