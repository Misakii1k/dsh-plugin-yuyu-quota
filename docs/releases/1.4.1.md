# v1.4.1

修复设置面板里「检查更新」偶发失败的问题；功能与 1.4.0 的币种折算、浏览器覆盖一致。

## 原因

- 1.4.0 及更早版本把 Cloudflare 更新源 `version.json` 的超时设成 **1.5 秒**。当前网络下实测经常要 1.3–2 秒，一旦超过 1.5 秒就被判为失败。
- 更新源超时后，插件会并发请求 GitHub。仓库是私有的，匿名请求会得到 `HTTP 403`，`raw.githubusercontent.com` 得到 `404`，最终把整次检查拼成「检查失败」。
- 另外 `version.json` 里的 `releaseNotes` 字段没有被读取，检查成功后也看不到发布说明。

## 修复

- 更新源超时从 1.5 秒放宽到 **6 秒**，避免把唯一可用的 Cloudflare 通道误熔断。
- 增加 `${updateFeedUrl}/api/releases` 作为二级通道：`version.json` 超时或返回 500 时，仍能从 Cloudflare 代理拿到 Release 信息。
- 读取 `releaseNotes` 字段，检查更新后能正常展示发布说明。
- 更新错误改成可读短句：`请求超时`、`请求被 GitHub 拒绝（403，仓库私有或触发限流）`、`未找到发布清单（404）`，不再只显示 `This operation was aborted`。

## 验证

- 新增 `scripts/update-test.mjs`，3 项通过：1.7 秒延迟的更新源、`version.json` 无新版本时 `/api/releases` 兜底、`version.json` 500 时兜底。
- 真实网络检查：约 1.45 秒返回 `1.4.0`，`source=feed`，不再出现超时/403 拼接错误。
- `npm test` 全量通过。
